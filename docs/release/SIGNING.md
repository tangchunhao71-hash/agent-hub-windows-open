# 签名状态与正式分发条件

本项目没有可用的 Windows 可信代码签名证书，也没有 Apple Developer ID、对应私钥或公证凭据。当前构建是明确标注的未签名/未公证候选，不把自签名当成普通用户机器信任的发布者签名，不安装自签根证书，不要求关闭系统防护。

源码和随包协议解决使用、版权与归属问题；签名用于核验发布者和文件完整性。两者不能互相替代，签名也不能替代安装与功能验收。

Windows 正式签名需要可用于本项目的可信代码签名证书及对应签名方式。应在构建安装器之前签好主程序与引擎，再签安装器并验证。签名后仍不保证 SmartScreen 完全没有提示。当前 scripts/windows-signature-report.ps1 只读验证 Authenticode；不生成、导出或导入私钥。

Mac 要在默认 Gatekeeper 条件下提供正常的外部分发体验，需要 Apple Developer ID 签名和 Apple 公证。应签好可执行程序与 app bundle，提交公证并附加票据，然后重新打包、验证和计算哈希。当前脚本验证 codesign、Gatekeeper 和 stapler 的实际结果，不把 ad hoc 签名或仅 codesign 验证成功记为可信公证。

设置进程级 AGENTBOT_REQUIRE_TRUSTED_SIGNATURE=1 时，打包入口必须拒绝缺少可信签名的产物；Mac 还必须有可验证的公证票据。默认候选模式保留真实的 false 状态。没有证书时只能完成候选包，不能声称“签名已做好”或自动获得正式售卖结论。

证书和账号接入由持有人提供，不写入源码、日志或普通聊天，不擅自购证、注册付费计划、创建持久凭据或上传私钥。正式签名的账号、主体和预算未确定前，签名步骤保持未完成。
